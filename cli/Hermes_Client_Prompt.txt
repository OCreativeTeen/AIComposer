## 核心交互原则与规则

1. **指令与状态确认**：
   - Telegram Bot 在收到耗时指令后会先回复 `⏳ [界面]/[长任务] 已开始 [ID] 命令`。此时必须等待，直到收到对应的 `ok [ID] 命令` 完成消息。
   - 若 Bot 提示 `⚠️ [ID] 命令 已经跑了 xxx 秒还没结束`，属于正常长任务现象，请继续耐心等待，无需重复发送指令，直至收到 `ok [ID] 命令`。

2. **异步轮询（Polling）**：
   - 对于查询类长任务（如 `nbif`），若 Bot 返回 --> “仍在生成中/未 ready”（如 `Studio 右侧列表里还有 Generating 项`），你必须**每隔 60 秒**重新发送一次 `nbif`，循环轮询，直到 Bot 回复 --> `三张/新的 infographic 已经 ready`。

3. **人工干预（Human-in-the-Loop）**：
   - **绝对禁止自动化接管封面选择**：当 Bot 完成 `itc` 命令并向 Telegram 发送 3 张封面图、提示“请选一张整篇故事封面：回复 1 / 2 / 3”时，**Agent 必须挂起/暂停操作，等待人类（Wenjun）在 Telegram 中手动输入选图指令**（例如发送 `itc 3` 或 `3`）。
   - 收到人类用户的选图指令并在 Telegram 中确认已被 Bot 记录后，Agent 再恢复自动化流程。

4. **主循环（Main Queue Loop）**：
   - 当一个故事流程结束（Bot 下载完所有 `grok_scene_*.mp4` 视频片段，并重新打印 `【听筒同步】STORY` 队列信息）后，Agent 需自动进入下一个故事的循环处理，直到队列中没有新的故事为止。

## 标准执行状态机 (Workflow State Machine)

请严格按照以下步骤顺序执行：

PRE-TASK (launch Telegram Bot):

    * Switch to the opened Doc-Command windows  
	* Goto - D:\AIComposer\cli 
	* Run  - run_bot.bat


### 步骤 1：挑选故事 (Pick Item)
- **动作**：若 Bot 当前处于 `【听筒同步】none` 或处于故事队列主界面，发送 `pick`（或按顺序 `pick 1`）。
- **期望返回**：`【听筒同步】STORY ... 可发：scn save pub ...`
- FYI：　这一步 AICOMPOSER　可能会 跳过 直接自己选一个 故事 

### 步骤 2：开启场景 (Open Scene)
- **动作**：发送 `scn`
- **等待**：直到收到 `ok [...] Scn` 并且 `【听筒同步】SCENE`。

### 步骤 3：选择 LM 提示词 (Select LM Prompt)
- **动作**：发送 `lm 4`
- **等待**：直到收到 `ok [...] Lm 4`（确认 LM 已切换为 4 Step Story）。

### 步骤 4：Gemini 生成故事场景 (Generate Story Scenes)
- **动作**：发送 `gem`
- **等待**：长任务（约 20-50 秒），直到收到 `ok [...] Gem`（提示 scenes on clipboard）。

### 步骤 5：写入场景并保存 (scnsave)
- **动作**：发送 `scnsave`（原 `pst` + `save` 已合并：剪贴板 JSON → scene_content → 写入 video_detail，**不关 SCENE 窗**）
- **等待**：直到收到 `ok [...] scnsave`（提示 `scnsave ok — N scenes saved to video_detail`）。

### 步骤 6：生成 Infographic 预设 (NotebookLM Preparation)
- **动作**：发送 `nbp 1`
- **等待**：直到收到 `ok [...] Nbp 1`。

### 步骤 7：触发 NotebookLM 生成 (NotebookLM Infographic Trigger)
- **动作**：发送 `nbi 1` … `nbi 5`（按 Chrome 账号轮换）
- **等待**：长任务（约 165 秒），直到收到 `ok [...] Nbi 1`。
- FYI :   `nbi 1` … `nbi 5` 对应以不同 Profile 打开 HermesChromeCDP（1. `ocreativeteen@gmail.com`   2. `creative4teen@gmail.com`   3. `triumphdt777@gmail.com`   4. `myhomefun@gmail.com`   5. `mindstoryroom@gmail.com`）以此来突破每一个账户对 NotebookLM 使用的限制  

### 步骤 8：轮询检查生成状态 (Poll Infographic Status)
- **循环动作**：
  1. 发送 `nbif`；
  2. 检查返回结果：
     - 若包含“仍在生成中 / Generating”，**等待 60 秒**，返回第 1 步重新发送 `nbif`。
     - 若包含“三个新的 infographic 已经 ready”，进入【步骤 9】。
- **超时（全自动 client）**：至少轮询 **5 分钟**、最长约 **40 分钟** 仍 not ready → client **退出**，**不关 Chrome**，队列条目标为 `nbif_timeout`。
- **恢复**：人工打开 NotebookLM 确认 ready 后，运行 **`cli\run_telegram_client_resume.bat`** — **不重开 Chrome**，直连下载封面 → 选封面 → **grv 前自动 scn（SCENE 未开时）**。

### 步骤 9：打开并下载封面图 (Download Infographics)
- **动作**：发送 `itc`
- **等待**：长任务（约 72 秒），直到 Bot 在 Telegram 发送 3 张图片并提示“请选一张整篇故事封面”。

### 步骤 10：【人工介入】等待用户选图 (Human Selection)
- **状态**：**暂停自动化逻辑**，等待人类用户（Wenjun）在 Telegram 输入选择命令（如 `itc 3` 或 `3`）。
- **恢复条件**：人类发送选择后，收到 Bot 的 `ok [...] itc ok — 已选 #N`（如 `selected_path=...`）。

### 步骤 11：生成 Grok 场景图与视频 (Grok Video Generation)
- **动作**：发送 `grv 1 3`
- **等待**：超长任务（约 300~900 秒），中途忽略超时警告，直到收到 `ok [...] Grv 1 3`，且确认所有场景 `grok_scene_*.mp4` 下载完成。

### 步骤 12：循环处理 (Next Story)
- **动作**：Bot 会重新打出 `【听筒同步】STORY`。
- **逻辑判断**：若仍有剩余故事，回到【步骤 1】（或直接发送 `pick`）继续处理下一个故事；若队列清空则任务结束。
